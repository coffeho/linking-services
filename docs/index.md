# HR System Documentation

HR System — учебный проект системы кадрового учета на Python и Tkinter.

Документация описывает текущее состояние проекта, предметную область, архитектуру, автоматизированные проверки и процесс командной работы.

## О проекте

HR System предназначена для базового кадрового учета организации.

Система включает:

- авторизацию пользователей;
- учет сотрудников;
- работу с подразделениями;
- работу с должностями;
- учет отпусков;
- кадровые приказы;
- переводы сотрудников;
- отчеты и статистику.

Проект развивается постепенно: от исходного монолитного файла `main.py` к структурированному инженерному проекту с выделенным `app/ui`, `packages/core`, тестами, документацией и автоматизированными командами.

## Основные команды

Подготовка окружения:

```bash
python3 -m venv .venv
source .venv/bin/activate
make setup
```

Основная проверка проекта:

```bash
make check
```

Команда `make check` запускает:

```bash
make test
make docs
```

Запуск всех тестов:

```bash
make test
```

Ожидаемый результат зависит от текущего количества тестов, но все тесты должны проходить без ошибок.

Запуск integration-тестов:

```bash
make integration-test
```

Сборка документации:

```bash
make docs
```

## Тестирование

В проекте используются несколько уровней тестов.

### Smoke-тесты

Smoke-тесты фиксируют базовое поведение исходного монолита:

- импорт `main.py`;
- создание таблиц;
- загрузку демонстрационных данных.

Запуск:

```bash
make smoke-test
```

### Unit-тесты

Unit-тесты проверяют отдельные core-модули:

- авторизацию;
- доменные модели;
- сотрудников;
- подразделения и должности;
- отпуска;
- переводы;
- приказы;
- отчеты.

Запуск всех unit- и smoke-тестов вместе:

```bash
make test
```

### Integration-тесты

Integration-тесты проверяют совместную работу нескольких core-модулей и временной SQLite-базы.

На текущем этапе integration-тест проверяет сценарий увольнения через кадровый приказ:

- создаётся временная SQLite-база;
- создаётся приказ на увольнение;
- приказ исполняется;
- статус сотрудника меняется на `Уволен`;
- статус приказа меняется на `Исполнен`.

Запуск:

```bash
make integration-test
```

## Проверка документации

Документация собирается автоматически через MkDocs:

```bash
make docs
```

Сгенерированный результат помещается в папку:

```text
site/
```

Папка `site/` не редактируется вручную и не хранится в Git, потому что документация должна пересобираться из исходных файлов в `docs/`.

## Переиспользуемый core-компонент

Переиспользуемая логика проекта находится в:

```text
packages/core/
```

Core-компонент можно установить локально:

```bash
make install-lib-local
```

И собрать как Python-пакет:

```bash
make build-lib
```

## Контейнерная проверка

Контейнер используется для воспроизводимого запуска проверок, а не для открытия Tkinter GUI.

Сборка образа:

```bash
make docker-build
```

Запуск проверки внутри контейнера:

```bash
make docker-check
```

Проверка через Docker Compose:

```bash
make compose-check
```

## Ограничения текущей версии

Проект всё ещё находится в процессе рефакторинга.

На текущем этапе:

- Tkinter GUI вынесен в `app/ui/main_window.py`, но отдельные формы пока не разделены по файлам;
- `main.py` оставлен как совместимая обертка для старого запуска и smoke-тестов;
- слой хранения `storage.py` пока находится внутри `packages/core`;
- контейнерная проверка запускает тесты и документацию, но не открывает GUI;
- дальнейшие улучшения будут выполняться отдельными Pull Request.
